# 実装計画 v2 — His Footsteps

（v1の計画書は `archive/実装計画_v1.md` に退避）

## 0. v1の何がダメだったか（作り直しの理由）

v1（プロトタイプ）は、企画書の意図に対して以下が決定的に欠けていた。

| 症状 | 根本原因 |
| --- | --- |
| 振動が弱い | `hapticTransient` を sharpness 1.0 で単発しか鳴らしていなかった。これは物理的に「カチッ」という点にしかならない |
| グルーヴを感じない | 拍検出が単純なエネルギーピーク。拍の間隔がバラバラで、キック/スネア/ハットの区別もない |
| 足跡がただ動き回るだけ | 左右交互＋上下ジグザグの4点をループしていただけ。振り付けが存在しない |
| UIがつまらない | SFシンボルの足跡が `.thinMaterial` の四角の上を動くだけ。照明も奥行きもない |
| 音とズレる | 曲の全長ぶんのハプティクスを一括予約し、`Date()` 基準で足跡を動かしていた |

→ アーキテクチャごと作り直した。

## 1. 設計の芯

**すべてを「1つの時計」と「1つの地図」から駆動する。**

- 時計 = `AudioEngineController.currentTime`
  オーディオのレンダリング時刻から算出し、出力レイテンシを差し引いた「今耳に届いている位置」
- 地図 = `GrooveMap`
  曲を解析して得た拍・打点・エネルギーの設計図

ハプティクス・振り付け・ビジュアル・判定は、すべてこの2つだけを見る。
別々のタイマーを持たないので、原理的にズレない。

## 3. グルーヴ解析（Audio/GrooveAnalyzer）

1. STFT（vDSP・窓1024／ホップ512）で低(28-165Hz)／中(180-2200Hz)／高(2600-11000Hz)の振幅を時系列化
2. 帯域ごとのスペクトルフラックス → 局所平均・局所標準偏差で白色化（録音の癖・音量差を吸収）
3. 自己相関＋テンポ事前分布でテンポ推定 → 放物線補間で小数精度に
4. 動的計画法（Ellis法）で拍を追跡。テンポの揺れに追従する
5. **テンポの折り畳み**：76〜152BPMへ正規化。
   実測で 97BPM の曲が 195BPM（8分音符を拍と誤認）として出たため。
   そのままだと足跡が毎秒3歩超で追えず、16分グリッドも77msに詰まって触覚が団子になる
6. 低域の強さから小節頭（ダウンビート）を推定
7. 16分グリッド上で打点を分類
   - 拍の上は必ず鳴らす。1・3拍＝キック／2・4拍＝スネアのバックビートを軸に、
     片方の帯域が圧倒的なときだけ入れ替える
   - 拍の間はしきい値を超えたときだけキック／スネア／ハット／ゴースト
   - 小節頭の強さ上位12%をアクセント（キメ）に昇格
8. ビジュアル用に60Hzのエネルギーカーブを出力

### 実測値（Resources/Music の3曲、同アルゴリズムのPython移植で検証）

| 曲 | BPM | 拍数 | 拍間隔の標準偏差 | 打点/秒 | 内訳 |
| --- | --- | --- | --- | --- | --- |
| If You're Falling | 97.6 | 334 | 12.5ms | 3.37 | kick 274 / snare 186 / hat 167 / ghost 51 / accent 11 |
| 〃 (1) | 98.0 | 360 | 7.3ms | 3.56 | kick 268 / snare 197 / hat 275 / ghost 34 / accent 12 |
| 〃 (2) | 102.0 | 434 | 3.7ms | 3.90 | kick 253 / snare 254 / hat 253 / ghost 222 / accent 14 |

小節内16分の分布はキックが 0・8、スネアが 4・12 に集中しており、教科書どおりのバックビートが取れている。

## 4. ハプティクス（Haptics/）

### 「ズドン」の作り方
transient単発では点にしかならない。**低シャープネスのcontinuous（減衰エンベロープ付き）を重ねる**のが要。

| 打点 | 構成 |
| --- | --- |
| kick | transient(sharp 0.12) + continuous 0.15s(sharp 0.0, decay 0.13) + 余韻transient + 余韻continuous |
| snare | transient(sharp 0.85) + continuous 0.075s(sharp 0.55) + 抜けのtransient(sharp 1.0) |
| hat | transient(sharp 1.0, 弱) |
| accent | transient + continuous 0.34s + 余韻2発 + 尾のcontinuous |
| bed | 16分グリッド上の低周波うねり。低域エンベロープに追従。強い打点の近くは避ける |

### 同期
`HapticConductor` が120msごとに「今から0.5秒先まで」だけを予約し直す。
毎回オーディオの実再生位置に吸着するので、5分の曲でもズレが蓄積しない。

補正した要因：出力レイテンシ（Bluetoothは200ms超）、端末ごとの体感ズレ（設定で±60ms）。
**低電力モードではTaptic Engineが止まる**ため、UIで警告する。

## 5. 振り付け（Choreo/）

9種のステップ語彙を小節単位で組む：
サイドステップ／ボックス／クロス／ムーンウォーク左右／ジグザグ（8分）／キック／スピン／つま先フリーズ／スウェイ

- 小節エネルギーで難度を選択、8小節ごとに見せ場（スピン or フリーズ）
- 曲IDをシードにした決定的乱数なので、同じ曲なら常に同じ振り付け＝練習が成立する
- ステップの質ごとにイージングが違う（踏み込みは速く到達して静止、滑りは等速、溜めは3乗）

判定は拍の前後±0.16秒で最も近づいた瞬間を採用。PERFECT/GREAT/GOOD/MISSの4段階。

## 6. ステージ演出（Visual/）

ぼかしフィルタを使わず、放射グラデーション＋加算合成のみで発光を作る（60fps維持のため）。

- 遠近フロアグリッド（小節位相でスクロール、低域で明滅）
- 天井から降りる光の柱（足元を追う）＋足元の光溜まり
- 客席側から舐める2本の照明ビーム（小節位相で首を振る）
- 踏んできた足跡を繋ぐ発光した軌跡線
- 足跡は左右非対称なソール輪郭をベジエで描画（SFシンボルは廃止）
- 指のコメット軌跡、足跡に近づくと光の糸が濃くなる
- キック／スネア／アクセントで画面が揺れる
- 粒子（スパンコール／火花）、ビネット

## 7. 曲の入れ方

1. **アプリ内で追加**：選曲画面の「曲を追加」→「ファイル」アプリからmp3/m4a等を選ぶ（推奨）
2. **PCから**：iPhoneを繋いでファイル共有の "His Footsteps" にドラッグ
3. **ビルドに内蔵**：`Resources/Music/` に置いてビルド

## 8. 開発フロー（Mac無し・無料）

Windows + 実機iPhone のみ。ビルドはGitHub Actions（macos-15）。

- CIの結果とコンパイルエラーは、gh CLI無しでもGitHub REST APIのcheck-runs annotationsから読める
  （`.github/workflows/build.yml` が `error:` 行をannotationとして出力する）
- 実機配布はAltStore/SideStore（無料Apple ID）
- DSPのように「ビルドが通っても効いているか分からない」部分は、
  同じアルゴリズムをPythonへ移植して実曲に当て、数値で検証してからSwiftへ反映する
